# Evaluation results

`results.md` (tables), `results.json` (same numbers) and the two PNG plots are
generated by `python -m evaluation.report`; do not edit them by hand.

## Reproduce

```bash
pip install -e ".[dev,eval]"
# 1. benchmark tools: download the release binaries into evaluation/tools/<tool>/
#    gitleaks v8.30.1 (windows_x64.zip, sha256 d29144de...afc4e) and
#    trufflehog v3.100.0 (windows_amd64.tar.gz, sha256 e3e854de...f86d), checked
#    against each release's checksums file; the report refuses other versions
# 2. retrain the packaged model (optional, it is already trained)
python -m evaluation.train --output src/secrety/data/classifier.json
# 3. score everything and rewrite this folder
python -m evaluation.report --out docs/results
```

Corpora are generated at runtime from fixed seeds (train 1, validation 3,
test 2, timing 4) into `evaluation/corpora/` and are never committed.
`evaluation/tools/` and the tools' raw reports (`evaluation/results/raw/`) are
gitignored too. Timings depend on the machine (recorded in `results.json`).

## What is measured

- **Corpus**: files in 14 formats, each with several fake secrets (11 families:
  AWS, GitHub, Stripe, Google, Slack, JWT, passwords, URL credentials, private
  keys, high-entropy tokens) and look-alike decoys (12 families: Git SHAs,
  UUIDs, checksums, placeholder passwords, hashes, data URIs...). Four decoy
  families (lockfile integrity hashes, Docker digests, SSH public keys, hashed
  asset names) exist **only in the test split**.
- **Scoring**: a detection is a `(path, line)`. A secret is found if any line
  of its span is flagged; every flagged line outside a secret counts as a
  false positive, decoy or not. Same scoring for secrety, gitleaks and
  trufflehog.
- **secrety** is run without the path allowlist (the corpus folders are called
  `tests/`, `docs/`, which the default allowlist skips), with the bundled rules,
  default entropy thresholds, and, for the last variant, the packaged
  classifier. gitleaks and trufflehog run with their defaults
  (`trufflehog --no-verification`).
- **Training**: a logistic regression on secrety's own findings on the train
  corpus, with the runtime features. The threshold is picked on a separate
  validation corpus. The test corpus is never used for any choice.

## Fake markers

`AGENTS.md` asks for visibly marked fake values. Putting `FAKE`/`EXAMPLE` in
the value would hand every tool the label, so the markers live in a header
comment (`synthetic corpus: FAKE TEST DATA...`) on every file that allows a
comment, identical for secrets and decoys, and each file type holds both
labels. Checked on the pinned tools with a GitHub-token-shaped value:

| Value | gitleaks 8.30.1 | trufflehog 3.100.0 |
| --- | --- | --- |
| unmarked | found | found |
| marker as prefix after `ghp_` (`FAKE...`) | found | found |
| `EXAMPLE` or `TEST` inside the value | found | **missed** (known-false-positive word list) |
| unmarked value under `tests/`, or in a file with the header | found | found |

So a marker inside a value would have flattered trufflehog's precision and
cost its recall, and secrety's `value_placeholder` feature fires on the same
words. Decision: keep the feature as is (real code uses these words as
placeholders), keep markers out of the corpus values.

## Reading the numbers

- The corpus is synthetic and written by the same person as the classifier's
  features: the classifier's gain over `combined` shows it learned what the
  corpus separates, not what real repositories contain. Compare train and test
  tables for the generalisation gap (train F1 0.96, test 0.92); the decoy
  families it never saw generalise unevenly: lockfile hashes and Docker digests
  are dropped (0/45, 0/28 flagged), a hashed asset name is flagged 8/28 and
  an SSH public key 40/40 (see `results.md`).
- The classifier costs recall, and almost all of it is one family: the
  high-entropy tokens that no rule knows and that sit under a neutral name
  (`entropy_token`, 11 of 52 kept on the test corpus). Every rule-matched
  family keeps 100 %. The 18 features cannot tell such a token from a random
  identifier, so the model drops both. This is the trade-off to know before
  using `--classifier` as more than triage.
- trufflehog scores a low recall because it only has detectors for known
  services and, without verification, no generic password or entropy rule; its
  precision is perfect on this corpus. Its default is not a flaw, it solves a
  different problem than the generic rules here.
- gitleaks and trufflehog take about 1 to 2 s on 1500 files (see `results.md`); secrety is slower
  (pure Python, whole process including interpreter start-up).
- The entropy thresholds were not re-tuned on this corpus.
