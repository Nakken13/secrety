## 01-regex-detection — 2026-11-20
What: core scanner. `Finding` model (masking: <20 chars fully hidden, <=25 % shown; fingerprint = rule|path|commit|line-without-secret, never the secret nor line/column so it survives code shifts and cannot be brute-forced from a published report). YAML rule loader with strict validation (bool/str/version checks, I/O errors -> RuleError -> exit 2). 13 default rules (AWS id/secret incl. JSON + Terraform forms, GitHub classic + fine-grained, Stripe, Slack token/xoxe/xapp + webhook, Google, JWT, PEM incl. DH, PuTTY, URL credentials, generic quoted password incl. DB_PASSWORD/client_secret/SECRET_KEY/`:=`). `Detector` protocol + line-based `RegexDetector` (newline-only line numbers, two-level keyword pre-filter on one lowercase copy). `FilesystemSource` (one lstat per file, 8 KiB head sniff, UTF-16 BOM, NTFS junctions and symlinks never followed, unreadable paths counted). `scanner.scan` -> `ScanResult(findings, stats)`. CLI `secrety scan PATH [--rules] [--max-file-size]`, exit 0/1/2, Rich-escaped output.

Test fakes are assembled at runtime (tests/fakes.py) so the repo holds no literal secret-shaped string (self-scan + GitHub push protection). Unquoted .env/YAML values deliberately left to entropy (02) + classifier (04): a regex on them flags function calls.
Deferred: dedupe when generic and specific rules hit the same value (02); self-scan FPs to silence in 04 (tests/fakes.py, tests/test_cli.py, url regex matching itself in default_rules.yaml, pyproject `secrety = "secrety.cli:app"`); bounded-quantifier lint for custom `--rules` files; Rich reporters package (05).

## 02-entropy-detection — 2026-11-21
What: entropy detection + merging of duplicate findings + unquoted config secrets. `detectors/entropy.py`: Shannon entropy H = -sum p log2 p; tokenizer = runs of base64/URL-safe chars `[A-Za-z0-9+/_-]` (+ `=` padding) with min length built into the regex (cached per length, ~3x faster than filtering after), pure-digit tokens skipped, all-hex tokens classed hex; `EntropyDetector` emits `high-entropy-base64`/`high-entropy-hex` (method entropy, confidence 0.3-0.6 linear from threshold to charset max). `config.py`: `EntropyConfig` (base64 4.5, hex 3.0, min_length 20) validated once; CLI `--entropy-base64-threshold/--entropy-hex-threshold/--entropy-min-length`, one error path (RuleError is a ValueError) -> exit 2. `scanner.merge_duplicates`: per file, findings on the same line with overlapping spans grouped transitively (JWT = 1 regex match + 3 entropy tokens); winner = regex if any, then highest confidence, then earliest column; losers in new `Finding.also_matched` ((rule_id, method) tuples), `Finding.methods`; CLI prints "also: ...". New default YAML rule `generic-password-unquoted` (KEY=value / key: value, optional `- ` list marker and `export`, hyphenated keys, values starting with $ < { % skipped, first 256 chars reported), limited to config files by a new optional rule field `paths` (lowercase globs on the file name, "/" rejected). `iter_lines` moved to `detectors/base.py`. `Finding.masked` caps asterisks at 120. `docs/methodology.md`: formula, length/alphabet bounds, per-charset thresholds, merge order, known weaknesses.
Why some decisions: regex beats entropy whatever the confidence, because entropy confidence moves with the threshold (the reported rule and the fingerprint, which hashes rule_id, would flip when task 07 tunes thresholds) and an entropy token can be a fragment of a value cut by `!`/`.`; entropy confidence is not comparable across charsets (random hex 0.4-0.55, random 24-40 char base64 only 0.3-0.35 because H <= log2(len)). Unquoted values cannot be gated by entropy (10-char password <= 3.3 bits), so the rule relies on key + config-file path + value shape; it lives in YAML (AGENTS.md rule: rules are data, tunable via --rules), hence the generic `paths` field instead of a hard-coded detector. Rich `emoji=False`: a location `a.py:100:3` printed ":100:" as an emoji and crashed cp1252 consoles (bug from 01, surfaced by entropy's many findings). Test values built from short pieces at runtime so entropy does not flag the repo's own tests.
Deferred: false positives — pip's `cacert.pem` alone gives ~2,550 base64 findings; git SHAs/SHA-256 digests (~3.7 bits) exceed hex 3.0; alphabet literals and URL paths (04). Optional `max_length` for entropy tokens, i.e. dropping data URIs instead of only capping the mask (04). Fingerprint collisions between different entropy tokens with the same surrounding text, and lone entropy fragments leaving the rest of the value in the hashed context (baseline work). Threshold tuning (07).
Reviews: deep code review (10 items: 1-9 applied, 10 deferred above) + simplify (4 angles; applied token-regex speed-up, single CLI validation path, shared loader helper, "/" path check, also_matched; skipped max_length (behavior change, 04), removing Finding.methods (it is the "record all methods" API), widest-span winner (regex-first kept on purpose), log2 pre-check and precomputed rule ids (negligible)).
Key commits: d1e1d40 (feature), fed7006 (YAML list form, self-scan), 20b0f43 (review fixes), bf27727 (simplify) on crew/batch-a.
Tests: none — detection logic is a risky zone but fully covered by automated tests (240 pytest, 98.3 % coverage: known entropy values, tokenizer edge cases, thresholds/CLI options, merge order incl. transitive and regex-first cases, positive+negative cases for the unquoted rule and its path filter, emoji regression).

## 03-git-history-scan — 2026-11-21
What: `secrety scan PATH --git [--max-commits N] [--since DATE]` scans the history reachable from HEAD. `sources/git.py`: `GitSource` streams one `git log --patch --cc --unified=0` (GitPython `as_process`) and parses it itself (commit header sentinel `\x01sha\x00author\x00date`, C-quoted `+++ b/` paths with the trailing tab git adds to paths with spaces, `@@`/`@@@` hunk headers). Only added lines are scanned, one `SourceFile` per run of consecutive added lines with a new `line_offset` that the scanner adds to finding lines (findings point at the line of `git show <sha>:<path>`). Merges: a line is kept only if every parent column is `+` (clean merge = 0 new findings, evil-merge/octopus resolution lines reported). Binary = NUL in the first 8 KiB while added lines run unbroken from line 1 (as on disk); elsewhere a NUL line is scanned like any other, so a NUL cannot hide a secret (security hook + advisor findings), oversized file versions counted in `skipped_large`, subfolder PATH -> `:(literal)` pathspec + `--full-history`. `mark_removed`: `removed_later=True` when the secret (longest line if multi-line) is in no file of HEAD, any path, via `git grep -a -F -h -f -` (patterns on stdin). `scan_history()` is the CLI entry point (wraps GitError into ValueError, reports shallow clones via `.git/shallow`). `Finding`/`SourceFile` gained `author`, `date` (+ `Finding.removed_later`, `ScanStats.commits`). CLI prints `by <author> on <date>` and "removed from HEAD, still in history"; all untrusted text printed through `_safe` (control chars as `\xNN`, then Rich escape). New dependency gitpython>=3.1.41 (Windows search-path CVE fix floor). `tests/conftest.py`: `GitRepo` fixture (global/system config isolated, fixed dates one day apart, config through `GIT_CONFIG_*` env).
Why some decisions: one `git log -p --cc` process instead of GitPython Diff objects per commit (one spawn, and combined diffs are the only way to see conflict-resolution lines). "Removed later" means absent from all of HEAD, not just the same path: a moved secret is still exposed. The scanned repo is untrusted input: the review found four one-line silent bypasses, all fixed and tested — subfolder scan dropped merged side branches (history simplification -> `--full-history`), `log.showRoot=false` hid the root diff (`--root`), `i18n.logOutputEncoding=UTF-16` hid every commit header (`--encoding=UTF-8` + error if a `diff` line comes before any header), committed `.gitattributes` `* -diff` made every file "binary" (`--text` + own NUL sniff; `git grep -a`). Also forced: `--no-ext-diff --no-textconv`, prefixes, `--no-color`, `--no-show-signature`; reviewer checked core.fsmonitor/pager/gpg/diff.external/sshCommand never run. Secrets never on argv (process list) -> stdin. Early generator close kills git instead of raising exit 141 over the real error. Padding added lines with blank lines was replaced by `line_offset` (cost was file length x commits for big files).
Deferred: only HEAD-reachable commits (no `--all` branches/tags; help text says so) — candidate option for 06/08. stderr of the streamed `git log` is a pipe never drained (possible hang if git wrote >4 KiB of warnings; not reproduced). `--since` filters on committer date while the author date is shown. `CommitInfo` dataclass instead of flat commit/author/date fields (public `Finding.commit` type change, consider with 05 reporters). Plumbing (`rev-list` + `diff-tree`) or wholesale user-config isolation instead of per-flag hardening (would lose `safe.directory` from global config). Same secret reported once per commit when re-added/cherry-picked (dedupe/baseline). Self-scan of secrety's own history: 24 old fake test values (04).
Reviews: deep — code review (13 items: 1-5, 7-9 applied; 6 doc-only; 10 obsolete with stdin; 11-13 deferred above), automated security hook (argv secrets, attribute bypass, terminal escapes, late-NUL bypass: all fixed), simplify (4 angles; applied run excerpts/line_offset, scan_history entry point, try/except/else, substring match, constants, `_fail` sanitizing, fixture spawns; skipped CommitInfo, plumbing switch, config isolation, generic ScanStats label).
Key commits: bdd0b57 (feature), f378017 (hardening), 66538cf (simplify) on crew/batch-a; post-merge binary-sniff fixes 91628be + next commit on main. Linux not run locally (first Linux run = CI). `security-review` skill not run (covered by deep review + security-guidance hook).
Tests: none — git history scanning is a risky zone but covered by automated tests (283 pytest on Windows, 98 % coverage; 35 git-source tests incl. NUL-line differentials incl. merges/octopus, shallow, binary/large, CRLF, repo-config bypasses, argv spy; CLI integration test: secret committed then deleted found at the right commit and marked removed).

## 04-false-positive-reduction — 2026-11-21
What: false-positive filtering and a classifier. `allowlist.py`: default path globs (tests, lockfiles, examples) overridable through `.secrety.toml` (`[allowlist] paths / use_defaults / inline_ignore`, strict validation in `config.py`), inline `secrety:ignore` and `secrety:ignore[rule-id]` for any comment style (a malformed marker ignores nothing; `[rule]` must name the reported rule plus every merged regex rule). `features.py`: 18 numeric features per finding (entropy, length, charset, variable-name tokens, file extension, placeholder words). `classifier.py`: pure-Python logistic-regression inference from a versioned JSON model (`data/classifier.json`, stub weights until task 07), threshold configurable, behind `--classifier`; decision recorded in `docs/decisions/0001-classifier-format.md` (JSON over pickled joblib: no unsafe load, no sklearn-version fragility). Carried over from 01: secrety's self-scan is clean (allowlist + inline ignore on the url-credentials rule); custom `--rules` files are linted for unbounded quantifiers (warning); filesystem walk counts skipped links in `ScanStats` and treats only name-surrogate reparse points (symlink, junction) as links, so OneDrive placeholders are still scanned. `docs/methodology.md` documents allowlist, inline ignore and classifier; AGENTS.md map updated.
Why some decisions: JSON model keeps the scanner dependency-light and safe to load from an untrusted package; allowlisting is path-based and overridable because test fixtures are the main FP source while a silent over-broad ignore would hide real leaks, hence the strict marker parsing.
Deferred: moving the post-scan pipeline (allowlist -> classifier -> report lines) out of `cli.scan`, and the unbounded-quantifier lint out of `rules/loader.py` (private `re._parser`) into `rules/lint.py`; `Allowlist.from_mapping` to own its TOML keys; efficiency micro-gains (path split once per `_allowed`, precomputed scaling in `probability`); test helpers to remove repeated setup in test_cli/test_classifier; one `FeatureConfig`/Settings layer for flags vs file. Real classifier training (07).
Reviews: deep code review (fixes in a07ebb4) + simplify (4 angles; applied shared hex alphabet, inline-ignore early exit, cli/config/load_classifier simplifications; skipped the rest as behavior-affecting or outside the diff).
Key commits: c0eb8c1..a07ebb4, 47cd8c8, ef756e5 on crew/batch-a.
